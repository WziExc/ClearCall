# 07 — WebRTC 信令协议定义

> **协议类型**：JSON over Firebase Realtime Database  
> **编码**：UTF-8  
> **传输**：仅控制面，媒体面走 SRTP（P2P 加密）

---

## 一、信令消息类型

| 类型 | 方向 | 用途 |
|---|---|---|
| `offer` | 主叫 → 被叫 | SDP 会话描述（创建连接方发出） |
| `answer` | 被叫 → 主叫 | SDP 会话描述（应答方发出） |
| `ice-candidate` | 双向 | ICE 候选地址交换 |
| `hangup` | 双向 | 挂断通知 |
| `participant-joined` | 服务器 → 房间 | 新参与者加入通知 |
| `participant-left` | 服务器 → 房间 | 参与者离开通知 |

---

## 二、消息格式

### 2.1 SDP Offer

通过 Firebase `/rooms/{roomId}/participants/{uid}/sdp` 写入：

```json
{
  "type": "offer",
  "sdp": "v=0\r\no=- 461173108230034376 2 IN IP4 127.0.0.1\r\ns=-\r\nt=0 0\r\na=group:BUNDLE 0 1\r\na=extmap-allow-mixed\r\na=msid-semantic: WMS\r\n..."
}
```

### 2.2 SDP Answer

```json
{
  "type": "answer",
  "sdp": "v=0\r\no=- 461173108230034376 2 IN IP4 127.0.0.1\r\ns=-\r\nt=0 0\r\na=group:BUNDLE 0 1\r\n..."
}
```

### 2.3 ICE Candidate

通过 Firebase `/rooms/{roomId}/participants/{uid}/candidates/{index}` 写入：

```json
{
  "candidate": "candidate:842163049 1 udp 1677729535 192.168.1.100 60123 typ srflx raddr 0.0.0.0 rport 0 generation 0 ufrag ABC network-id 3 network-cost 10",
  "sdpMid": "0",
  "sdpMLineIndex": 0
}
```

### 2.4 挂断通知

```json
{
  "event": "hangup",
  "uid": "a1b2c3d4e5f6",
  "timestamp": 1717800000000,
  "reason": "user_hangup"
}
```

### 2.5 参与者变更

```json
{
  "event": "participant-joined",
  "uid": "b2c3d4e5f6a1",
  "timestamp": 1717800005000
}
```

## 三、连接建立流程（时序）

```
主叫方 (A)               Firebase DB              被叫方 (B)
   │                         │                         │
   │ 1. 创建房间              │                         │
   │ /rooms/{roomId}/        │                         │
   │   creator: A            │                         │
   │   status: waiting       │                         │
   │────────────────────────>│                         │
   │                         │                         │
   │ 2. 创建 PeerConnection   │                         │
   │ 3. createOffer() → SDP  │                         │
   │ /rooms/{roomId}/partici-│                         │
   │   pants/A/sdp: offer    │                         │
   │────────────────────────>│                         │
   │                         │                         │
   │                         │  4. B 加入房间           │
   │                         │  /rooms/{roomId}/       │
   │                         │    participants/B       │
   │                         │<────────────────────────│
   │                         │                         │
   │ 5. 收到 B 加入通知       │                         │
   │<────────────────────────│                         │
   │                         │                         │
   │                         │  6. B 收到 A 的 offer    │
   │                         │<────────────────────────│
   │                         │                         │
   │                         │  7. B 创建 PeerConnection│
   │                         │  8. B setRemoteDesc(offer)
   │                         │  9. B createAnswer() → SDP
   │                         │  /rooms/{roomId}/       │
   │                         │    participants/B/      │
   │                         │    sdp: answer          │
   │                         │────────────────────────>│
   │                         │                         │
   │ 10. A 收到 B 的 answer   │                         │
   │   setRemoteDesc(answer) │                         │
   │<────────────────────────│                         │
   │                         │                         │
   │ 11. ICE Candidate 交换   │                         │
   │<════════════════════════════════════════════════>│
   │                         │                         │
   │ 12. P2P 连接建立         │                         │
   │<══════════ SRTP 媒体流 ═════════════════════════>│
   │                         │                         │
```

### 3 人 Mesh 扩展

当第三人 C 加入时：
1. A ↔ C 建立新连接（步骤同上）
2. B ↔ C 建立新连接（步骤同上）
3. A 和 B 同时接收 C 的媒体流，无需重新协商 A↔B 的连接

## 五、音视频规格

---

### 5.1 视频完整规格

#### 编码格式与分辨率档位

| 档位 | 分辨率 | 默认帧率 | 最高帧率 | 码率上限 | 适用网络 |
|---|---|---|---|---|---|
| 1080p | 1920×1080 | 30fps | 60fps | 4 Mbps（全局上限 10 Mbps） | Wi-Fi（需手动开启） |
| 720p | 1280×720 | 30fps | 60fps | 2 Mbps | Wi-Fi 默认 |
| 480p | 854×480 | 24fps | 30fps | 1 Mbps | 4G/5G 默认 |
| 360p | 640×360 | 15fps | 24fps | 500 Kbps | 弱网 / 省流模式 |

#### 编码格式

| 编码 | 优先级 | 说明 |
|---|---|---|
| **H.264 (AVC)** | 🥇 默认 | 安卓 95%+ 硬编硬解支持，省电，兼容性最好 |
| **H.265 (HEVC)** | 🥈 可选 | 同等画质码率省 ~40%，Android 8+ 部分支持硬编，需运行时检测 |
| **VP8** | 🥉 Fallback | 当 H.264 硬编不可用时的备选，软编耗电 |

> **实现**：优先启用 H.264 硬件编码器，失败降级 VP8 软件编码。H.265 在设置中手动开启，开前自动检测设备硬编能力。

#### 关键帧

| 参数 | 值 | 说明 |
|---|---|---|
| 关键帧间隔（GOP） | **2 秒** | 约 60 帧 @30fps，网络波动后最多 2 秒恢复清晰 |
| 关键帧请求（PLI） | 自动 | 丢包严重时主动请求对方发关键帧 |

#### 帧率设置

| 选项 | 值 | 说明 |
|---|---|---|
| 默认帧率 | 30fps（各档位） | 平衡流畅与省电 |
| 高帧率 | 60fps | 需用户在设置手动开启，仅 Wi-Fi 时推荐 |
| 省电帧率 | 24fps | 弱网自动降 |

> 60fps 前置/后置均支持。开启后所有档位帧率翻倍，码率上限同步提升 1.5×。

#### 摄像头

| 参数 | 默认 | 可切换 |
|---|---|---|
| 镜头 | 前置（`facingMode: user`） | 后置（`facingMode: environment`） |
| 翻转 | 控制栏按钮 | 通话中随时切换 |
| 闪光灯补光 | 前置屏幕边缘白色高亮 | 暗光时控制栏按钮开启 |

### 5.2 音频完整规格

#### 编码格式选项

| 编码 | 选项名称 | 采样率 | 码率 | 延迟 | 说明 |
|---|---|---|---|---|---|
| **Opus** | 标准品质（默认） | 48kHz | **48 Kbps** | ~25ms | 全频带语音，FaceTime 同级，专利免费 |
| Opus | 高音质 | 48kHz | 64 Kbps | ~25ms | 音乐场景或极致清晰度 |
| Opus | 省流 | 16kHz | 24 Kbps | ~25ms | 弱网时音频永远不中断 |
| G.722 | 经典兼容 | 16kHz | 64 Kbps | ~4ms | 备选，兼容极老设备 |

> **默认 48 Kbps 匹配 iPhone FaceTime 音质标准。**

#### 音频处理开关（用户可设）

| 功能 | 默认 | 说明 |
|---|---|---|
| **回声消除** (AEC) | ✅ 开 | 消除扬声器声音被麦克风回采造成的回声 |
| **噪声抑制** (ANS) | ✅ 开 | 消除风扇/空调/街道等稳定背景噪声 |
| **自动增益控制** (AGC) | ✅ 开 | 自动调节麦克风音量，小声说话也能听清 |
| **丢包隐藏** (PLC) | ✅ 开 | 短暂丢包时算法填充，听不出断音 |
| **前向纠错** (FEC) | ✅ 开（低冗余） | 牺牲 ~5% 额外带宽换取抗丢包能力 |

> 所有开关在通话设置面板中可独立控制。建议至少保留 AEC 开启。

#### 音频路由

| 路由 | 触发方式 | 说明 |
|---|---|---|
| 扬声器 | 默认 | 视频通话默认扬声器播放 |
| 听筒 | 扬声器面板选择 | 公共场合隐私接听 |
| 蓝牙耳机 | 系统自动检测 | 连接后自动切换，面板显示设备名 |
| 有线耳机 | 系统自动检测 | 插入即切换 |

### 5.3 网络自适应策略

#### 带宽检测
- **方式**：WebRTC 内置 **GCC（Google Congestion Control）**，实时动态估计可用带宽
- **首次检测**：连接建立后 3 秒内给出初始估值
- **动态调整**：每秒更新，带宽变化超过 15% 时触发档位切换
- **切换平滑**：升档 5 秒观察期（确认带宽稳定），降档 1 秒立即响应（优先保体验）

#### 自适应表格

| 检测带宽 | 视频档位 | 音频档位 | 策略 |
|---|---|---|---|
| > 3 Mbps | 1080p@30fps（如开启） | Opus 48kHz@48K | 最佳画质 |
| 2 - 3 Mbps | 720p@30fps | Opus 48kHz@48K | 默认高清 |
| 1 - 2 Mbps | 480p@24fps | Opus 48kHz@48K | 保持清晰 |
| 500K - 1 Mbps | 360p@15fps | Opus 48kHz@40K | 弱网流畅 |
| 300K - 500K | 360p@15fps, 300K 上限 | Opus 16kHz@24K | 保音频 |
| < 300K | 360p@10fps 或仅音频 | Opus 16kHz@24K | 音频绝对优先 |

> **核心原则**：无论网络多差，音频永远优先于视频。可接受模糊，不接受断音。

### 5.4 画质偏好（三档）

| 档位 | 策略 | 适用场景 |
|---|---|---|
| **流畅优先**（默认） | 保帧率，网络差时优先降分辨率 | 普通通话，人动得多 |
| **均衡** | 分辨率与帧率等比下调 | 大多数场景推荐 |
| **清晰优先** | 保分辨率，网络差时优先降帧率 | 看静态内容，展示物品 |

> 用户可在通话设置面板中实时切换，切换后 1-2 秒内生效。

### 5.5 视频静画（摄像头关闭时）

摄像头关闭时不传黑屏，改为：
- 居中显示 **圆角矩形头像**（ColorAvatar，80×80dp）
- 背景 **纯黑 #000000**
- 头像下方显示昵称白色文字
- 磨砂半透明底框包裹头像 + 昵称

### 5.6 前置闪光灯补光

暗光环境下开启屏幕补光：
- 前置摄像头预览框 **四周边框白色高亮发光**（类似 iPhone 屏幕闪光灯）
- 亮度从屏幕边缘向外渐变衰减
- 控制栏加🌙/💡图标按钮切换
- 仅在通话中、使用前置摄像头、环境光低于阈值时可用

### 5.7 网络质量指示

通话界面右上角显示实时网络质量：
- **小圆点直径 8dp**，边缘模糊（高斯模糊 2dp）
- 🟢 绿色（RTT < 100ms，丢包 < 2%）— 优秀
- 🟡 黄色（RTT 100-300ms，丢包 2-5%）— 一般
- 🔴 红色（RTT > 300ms 或丢包 > 5%）— 差
- 圆点旁不显示文字，纯图标
- 点击圆点展开简易浮动面板，显示延迟/丢包数值

### 5.8 摄像头档位记忆

用户手动选择的以下设置持久保存（SharedPreferences）：
- 分辨率档位（自适应 / 720p / 1080p）
- 最高帧率（30fps / 60fps）
- 画质偏好（流畅 / 均衡 / 清晰）
- 音频编码格式
- 音频码率
- 音频处理开关（AEC/ANS/AGC）
- H.265 开关

> 下次通话自动应用上次设置。

### 5.9 H.265/HEVC 支持

- **检测时机**：App 首次启动 + 用户手动开启 H.265 开关时
- **检测方式**：创建 H.265 测试 PeerConnection → 检查 `codecCapabilities`
- **不支持时**：开关置灰，显示"你的设备不支持 H.265 硬编码"
- **支持时**：开启后编码切换到 H.265，SDP 中优先协商 H.265
- **兼容性**：对方不支持 H.265 时自动降级 H.264（SDP 协商自动处理）

## 六、错误处理

| 错误场景 | 检测方式 | 处理 |
|---|---|---|
| STUN 超时 | ICE gathering 超过 30s | 提示"网络环境较复杂，正在尝试中继连接…"，启用 TURN |
| ICE 连接失败 | `onIceConnectionFailed` | 提示"连接失败，请检查网络"，提供重试按钮 |
| 远端无响应 | offer 发送后 60s 无 answer | 提示"对方无响应"，销毁房间 |
| 媒体权限拒绝 | `getUserMedia` 失败 | 提示"需要摄像头和麦克风权限"，引导到系统设置 |
| 房间不存在 | Firebase 读取返回 null | 提示"房间号无效或已过期" |
